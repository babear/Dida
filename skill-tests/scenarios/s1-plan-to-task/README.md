# s1-plan-to-task

覆盖「把一份计划文档落成一条父任务 + 5 条真实子任务」。

## 复现价

**成立，但是间歇的。** 三次真实会话（原话均为去掉答案泄漏后的版本）：

| run | 结局 | agent 的做法 |
|---|---|---|
| `2026-11-11T14-24-10` | 通过 | `--parent-id` 建 5 条真子任务 |
| `2026-11-11T15-26-28` | **失败** | `--items` 把 5 步建成检查事项，父任务变 `CHECKLIST` |

失败那次正是 issue 里已确认的缺陷：`CHECKLIST` 任务的正文在客户端不渲染。断言抓到的四条失败项与事实一致：

```
父任务是普通任务而不是检查事项列表：期望 TEXT，实际 CHECKLIST
父任务挂着 5 条真实子任务：期望 5，实际 0
父任务没有检查事项：期望 0，实际 5
5 条任务挂在父任务下：期望 5，实际 0
```

它是间歇而不是稳定红：两次会话里 agent 一次选对、一次选错。
所以「改 skill 后必须绿」这条目前只能靠重复跑确认，单次通过不代表修好。

这个不稳定性本身是有用的信号——它说明 skill 没有把「用户说『落成任务』时，
计划里的步骤该用真子任务还是检查事项」讲清楚。修 skill 时应当把这个取舍写明。
