# 用字符串数组 `--items` 建检查清单

## 观察到的问题

`task create --items '["帐篷、睡袋", "气罐与炉头", ...]'`（**字符串**数组）不会报错，
但每一项都会被丢弃并告警，任务落成 `kind: TEXT`、`items` 为空。

agent 以为建成了检查清单，直到 `task get` 读回来才发现不对，再发一次 `task update --items`
改用逗号分隔补正。也就是说：**第一次写入白做了一次**，还多了一次读、一次改。

## 证据

`evidence.ndjson` 是 2026-11-17 那次运行的完整调用序列（`calls.ndjson` 脱敏，只留
`argv` 与 `decision`）。第 8 条是错的写法，第 9 条读回看到 `kind: TEXT`，
第 11 条用逗号分隔补正。

同一形状在 11-17 的 5 次运行里都出现过：

## 为什么是 skill 的问题

`skills/dida-cli/references/task.md` 只描述了 `items[]` 的字段结构，**从没写过 `--items`
该传什么格式**。agent 每次都在猜：猜成字符串数组就白建一次，猜成对象数组或逗号分隔就对。

正确的写法有两种，任选其一：

- 逗号分隔：`--items '帐篷、睡袋,气罐与炉头,头灯'`
- 对象数组：`--items '[{"title":"帐篷、睡袋","status":0}]'`

## 这条规则判什么

**禁止「用字符串数组 `--items` 建任务」这个动作**，以及它之后的 `update --items` 补正。

不判路径：一次用逗号分隔或对象数组建对、先读文档再建、建完再读，都不命中。

## 什么时候可以删

`task.md` 写明 `--items` 的格式之后，agent 不会再试字符串数组，这条规则会一直绿。
**绿了不代表可以删**——它的作用是防止改动 skill 时把这个坑重新踩回去。
只有当这条用例连同它要防的缺陷一起被移除时才删。
