# ADR-0003：用真实 agent 会话评测 skill，而非静态检查或 CLI 回归

- 状态：接受
- 日期：2026-11-06

## 背景

`dida-cli` skill 的三份文档描述了命令取舍、字段语义与「读 → 改 → 验」流程，但从未被验证过。一份 2026-11-05 的使用反馈记录了六条缺陷，其中权重最高的一条是：`--content` 与 `--items` 同时使用时，`task get --json` 返回正文非空，客户端却不渲染。

要证伪"skill 改了"这件事，可选的评测面有三层：CLI 二进制本身、skill 文档的静态结构、agent 在 skill 引导下的实际行为。前两层都回答不了"agent 会不会重蹈覆辙"。

## 决定

**只在 agent 会话这一层设测试接缝。** 每条 scenario 启动一个全新的一次性 `claude -p` 子进程，给它用户原话和沙箱素材，会话结束后读测试清单的最终状态与该会话的调用序列做断言。

不建 CLI 层与 shim 层的独立测试接缝。CLI 层的断言测的是 npm 包，改 skill 永远不会让它变绿；shim 层只验防护逻辑，是 harness 的基础设施，不是被测对象。

## 后果

- 每条 scenario 是一次真实 API 会话，成本约 $0.03–0.3、耗时约 1–2 分钟，全量一轮是分钟级而非秒级。
- 测试结果带模型抽样波动，需要失败重试一次（见 ADR-0006）。
- 收益是：只有这一层能区分"skill 让 agent 做对了"和"skill 没让 agent 做错"。
