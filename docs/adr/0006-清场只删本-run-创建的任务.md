# ADR-0006：清场只删本 run 创建的任务，禁止按清单清空

- 状态：核心规则仍有效；「运行前检查清单为空」与「遇未记账任务停止」两条约束已被 ADR-0010 取代
- 日期：2026-11-06

## 背景

设计阶段做事实核验时，我为清理自己创建的 3 条探针任务，执行了"列出测试清单全部任务并逐条删除"。那次删除数是 4——第 4 条是用户手动创建、标题为 `d` 的任务，被一并删掉了。

随后确认 Open API 没有回收站：CLI 只有 `delete`，`GET /project/{id}/data` 不返回已删任务，`/trash`、`/task/deleted`、`/recycle` 等端点全部 404 或 405，删除是硬 `DELETE`。**该任务无法恢复。**

而 harness 的测试清单里，用户的真实数据与 harness 产生的临时数据是共存的——测试清单同时承担"隔离区"和"用户可见的清单"两种角色。

## 决定

**harness 永不清空清单。** 它创建的每一条任务在创建后立刻记入 `runs/<runId>/created.json`，清理时只删该文件里记录的 id。不做任何形式的按清单扫描删除。

清单里出现非本 run 创建的任务时，harness 只报错并停止，不动手。

清理另有两条约束：每次运行前检查测试清单是否为空，不空则拒绝运行并列出可疑任务由用户处置；运行失败时保留现场，由显式的 `clean` 命令清理。

## 考虑过的方案

- **按标题前缀清理**：比清空安全，但仍是按规则扫描，前缀规则写错一样会误删。
- **运行前清空清单**：隔离最彻底，但会抹掉用户的真实数据，也正是这次事故的做法。

## 后果

- 测试清单必须保持为空才能开跑，用户手动建的任务会被检查拦下而不是删掉。
- 失败现场默认保留，`runs/` 需要清理策略，否则会持续增长。
