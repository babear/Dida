# ADR-0005：过程断言不违反"勿断言调用顺序"

- 状态：接受
- 日期：2026-11-06

## 背景

`tdd` skill 的 `tests.md` 把"断言调用次数/顺序"列为反模式，理由是这类测试与实现耦合，重构未改行为时也会失效。

本项目的 scenario 恰恰要看调用序列：缺陷不只表现为结局错误，也表现为"结局侥幸正确但过程中绕远路"。例如先建一个 `CHECKLIST` 任务、发现正文不显示、再删掉重建为 `TEXT`——最终状态完全正确，但这次会话的 skill 引导是失败的。

## 决定

**过程断言合法，但只写已确认的硬规则。** 判定依据是调用序列，不覆盖"用了什么巧妙的替代做法"这类主观判断。当前只允许三类：

1. 不存在"创建带 `--items` 的任务后删除重建"的序列；
2. 不存在"`content` 从非空变为空"的更新；
3. 不存在目标清单不在测试清单集合内的写调用。

质量维度（绕路、冗余操作、是否先读后改）交由判定 agent 写进报告，**不影响通过或失败**。

## 理由

`tdd` 那条反模式的前提是"存在一层被绕过的实现细节"。本项目没有这一层：被测对象是 skill 文档，agent 的工具调用轨迹就是它的公开行为，不存在"重构后行为不变但调用序列变"的情形——调用序列变化本身就是行为变化。

## 后果

- 过程断言必须与结局断言共同决定结果，任一项失败即为失败。
- 新增过程规则前，必须有一次真实会话证明该规则对应已确认的缺陷，否则容易演变成给模型写剧本，把"更聪明的替代做法"误判为失败。
