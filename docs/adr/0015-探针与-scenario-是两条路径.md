# ADR-0015：探针与 scenario 是两条路径，共用会话门、可信度检查与取快照

- 状态：接受
- 日期：2026-11-17

## 背景

ADR-0012 把探针写成「没写 `assert.mjs` 的 scenario」，并在同一节的末尾补了一句「探针跑完整链路」。ADR-0014 则写着「`probes/` 与 `scenarios/` 是两条独立流程：探针不参与判定，因此不受本 ADR 的判定链与清场门控约束」。两句冲突，实现无法照着任一句落地。

冲突的根源在于「探针 = 缺断言的 scenario」这个定义本身：如果探针是一条 scenario，它就该继承 scenario 的判定链（会话门 → 可信度 → 快照 → 结局断言 → 过程断言）与清场门控，而它要做的恰恰是「只看事实、不下结论」。按那个定义，探针要么被判定链拦在快照之前（ADR-0014 的严格短路下，不可信即停），要么被迫在一条流水线上加 `kind` 分支，把「判定链在第几面停」这个知识搬进编排层。

## 决定

### 分岔点在快照之后，不在沙箱之前

两条路径共享前三步，完全相同：

```
沙箱 → 会话 → 账本与调用日志
      ↓
会话正常结束？   不过 → incomplete，停
      ↓ 是
可信度检查       不过 → invalid，停
      ↓ 通过
取终态快照
      ↓
   ┌──┴────────────────────┐
   ↓                       ↓
探针：到此为止           scenario：结局断言 → 过程断言
结论 sampled            结论 passed / failed / broken
```

**探针也要过会话门与可信度检查**，理由是：快照是断言的输入，而探针存在的全部意义就是产出写断言的依据。可信度不通过时调用日志可能不全、快照所依赖的这次运行可能被绕过，据此写出的断言没有意义。所以那种情况下探针判 `invalid` 并停——不是「照跑并在报告里标注风险」。

这条与 ADR-0014 的「探针不受判定链约束」措辞不同，但含义一致：探针不受**三面判定**约束（不判断言、不判 `passed`/`failed`），而会话门与可信度检查不是三面，是两条路径共享的前置条件。

### 结论词汇

| 结论 | 含义 |
|---|---|
| `sampled` | 会话正常结束、可信度通过、快照已落盘。这是探针唯一的成功结论 |
| `incomplete` | 会话没正常结束，判定链未开始 |
| `invalid` | 可信度不过、轨迹读不出，或快照取不到（cause 沿用 scenario 的 `cross-check` / `indeterminate` / `state`） |

`incomplete` 与 `invalid` 在两条路径上含义相同，沿用同一批词（ADR-0014「状态名对外统一」）。成功**不能**叫 `passed`：`passed` 意味着三面全过，而探针没有任何一面被判定过，用会让读者以为 skill 是对的。

探针的退出码只反映「这份样本可不可用」：`sampled` 为 0，其余为 1。没有 `failed`——探针不判 skill 对错。

### 探针永不自动清场

探针的全部价值是现场：任务、沙箱、`runs/<runId>/`、`state.json` 都要留着，人才能打开客户端对着看、据此写断言。收尾只走 `--clean <runId>`。

不提供「探针模式下的自动清场」也不做交互确认：前者会让「探针不清场」从结构保证退化成人的记忆，后者会让 harness 不能进脚本。

### 编辑层形状

- `loadScenario` 返回 `{ id, dir, kind: 'scenario' | 'probe' }`，查找顺序是先 `scenarios/` 后 `probes/`——**同名时正式用例优先**，避免「以为在测正式用例，实际跑的是探针」。
- 「会话门 → 可信度 → 取快照」抽成一个共享阶段；`decideAssertion` 退化为「接一份已取好的快照 → 跑断言」。编排层不出现 `if (kind === 'probe')`。
- manifest 记 `kind`，`runs/` 共用不分目录，`--clean` 两边通用。
- `probes/<id>/` 里的 `assert.mjs` 不执行，也不报错（沿用 ADR-0012），但控制台与报告各留一行提示「未被使用」——静默忽略会让「写了断言却没结论」变成无声的困惑。
- 探针可以带 `preset.mjs`，校验规则与账本归属完全同 scenario。

### 全量运行不碰 `probes/`

现状 `listScenarios` 只扫 `scenarios/`，这一条天然成立。新增的只有一处：全量运行结束时若 `probes/` 非空，汇总末尾提醒清理——`probes/` 里有东西说明流程没走完。

## 被否掉的替代方案

**一条流水线加 `kind` 分支。** 它把「判定链在第几面停」的知识放进编排层，`decideAssertion` 的注释与测试会变成谎言；而两条路径真正的分岔只有快照之后这一段，用分支表达等于把共享的部分也拆开了。

**独立的 `harness/probe.mjs`。** 沙箱、账本、快照、报告全要复用，等于两套维护面；将来改判据（#18）要改两处。

**探针不取快照、只留轨迹与调用日志。** 被否：`state.json` 正是写断言的依据（断言按字段定位任务，`tasks` 就是快照），没有它探针就只剩下给人读的轨迹。

## 后果

- ADR-0012 的「探针是没写断言的 scenario」一节作废，原文保留、加取代说明。
- `GLOSSARY.md` 的探针词条重写；「判定」「清场」「终态快照」三条各补一句「探针不走这条」。
- `harness/README.md` 与 `skill-tests/README.md` 里「探针归 #20」「#20 落地前只能放 `scenarios/` 里跑」这类现状描述改写。
- 探针的第一次真实使用是 #25 的 `CHECKLIST` 用例：先在 `probes/` 里跑出 `state.json`，据此写断言，再 `git mv` 进 `scenarios/`。
- 探针不计入回归网。`probes/` 里有残留不影响退出码，只在汇总里提醒。
