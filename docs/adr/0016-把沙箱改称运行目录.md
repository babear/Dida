# ADR-0016：把「沙箱」改称「运行目录」，并明确它不是隔离边界

- 状态：接受
- 日期：2026-11-18

## 背景

项目此前把每次运行建的临时目录树称为「沙箱」。这个词在操作系统、容器、浏览器里都有公认含义：**限制进程能访问的资源**。而这里实际做的只是把 cwd 设到 `%TEMP%/run-<runId>/work/`，再把 skill、settings、shim 复制到同级目录——文件系统其余部分完全可读写。

用词与事实的错位造成了实际的认知成本：`docs/specs/issue-沙箱不隔离文件系统.md` 这个文件名本身就是症状——一个叫「沙箱」的东西，名字里写着「不隔离文件系统」。第一次读到的人会先建立错误预期，再被纠正；而文档越写「已知边界：沙箱不隔离文件系统」，越像在说「这个沙箱有 bug」，而不是「它本来就不是沙箱」。

## 决定

把面向读者的称呼从「沙箱」改为「**运行目录**」（run directory）。它准确、不承诺隔离，且与 `run-<runId>/` 的命名天然对应。

**不改代码标识符**：`createSandbox`、`sandboxRootOf`、`sandbox.mjs`、`--keep-sandbox`、`manifest.sandboxRetained` 等保持原样。理由是改名的收益在读者理解，而标识符改名会影响 API、测试与历史运行产物，产生大量无意义 diff。

**不改机器可读的输出格式**：报告首行的 `sandbox <path>`、控制台的 `sandbox=` 键名、manifest 的 `sandbox` / `sandboxRetained` 字段都保留英文原名。这些是给脚本解析的，不是给读者读的散文；改键名会让既有 `runs/` 产物的解析逻辑失效。中文散文里的称呼才改。

**ADR 历史原文不改**：0003、0004、0008、0011、0012、0013、0015 里的「沙箱」是当时的用词，按本项目惯例保留。

## 后果

- `GLOSSARY.md` 新增「运行目录」词条，并把「沙箱」「sandbox」「隔离环境」列进 `_Avoid_`。
- README、spec、代码注释、测试名里的「沙箱」全部替换；ADR 与 `docs/specs/issue-沙箱不隔离文件系统.md`（#3 的原始存档）保留原样。
- 文档里原先「沙箱只隔离工作目录」的表述改为「运行目录不是隔离边界」——前者把 cwd 说成了一种约束，后者才是事实。

## 考虑过的方案

- **叫「工作区」**：容易与 `work/` 这个具体子目录混淆。
- **叫「临时运行环境」**：准确但冗长，每次提都要多写两个字。
- **保留「沙箱」并强制加限定语**（如「沙箱（非隔离）」）：历史文档不用动，但每次提到都要解释一遍，成本更高。
- **连标识符一起改**：彻底，但 `createSandbox` 这类名字已经出现在历史 run 产物与 ADR 里，改名会让新旧对不上。

已知残留的混淆：控制台与报告里还有 `run dir=<runs/...>`（指产物目录，不是这里说的运行目录）。两者中文都含「运行目录」，但上下文足够区分——前者永远带 `runs/` 前缀。若将来真造成误读，改的是那个控制台键名，不是本词条。

## 与 #3 的关系

这次只改称呼，**不改变任何运行时行为**。`PowerShell` 在工具面上时无法限制文件访问，这一点（#3）没有解决也不打算在本 ADR 解决；本 ADR 只是不再用「沙箱」这个词暗示一个不存在的能力。
