# ADR-0001：dida-cli skill 按命令域拆分，README 降为校对源

- 状态：接受
- 日期：2026-10-21

## 背景

一次使用 dida-cli 的会话中，agent 反复误判 CLI 能力、误用命令、用陈旧数据汇报现状。复盘后确认两条结构性原因：`SKILL.md` 里抄写的命令细节与已安装 README 重复，而 README 独有的字段语义又被「去读 README」外包给运行时，导致执行路径又长又容易跳过。

安装版本 `0.1.14` 的 `--help` 经逐条核对，已完整覆盖所有子命令、参数、枚举取值、日期格式与 `--json`。它给不出的是：返回结构、字段含义、规则语法（`reminders`、`repeatFlag`）与行为边界。

## 决定

1. **按命令域拆分**：新增 `references/task.md`、`references/project.md`。只拆这两个域——README 独有的知识全部落在这两域；habit / focus / tag / countdown / preference 的 `--help` 已完整覆盖，单独建文档只会复制参数。
2. **参数委托给 `--help`**：域文档不写命令参数表，只写 `--help` 给不出的内容——能力缺口、跨命令取舍、返回字段、规则语法、实测与文档不符处。
3. **README 降级为校对源**：字段表、`reminders` / `repeatFlag` 语法、请求体映射搬进域文档并标注版本 `0.1.14`。版本不一致时以已安装 README 为准。版本校对与安装、登录合并进 `SKILL.md` 的前置检查，同一时点执行。
4. **查询路由留在 `SKILL.md`**：四条查询路径横跨两个域（`project data` 属清单域却返回任务），拆进域文档会失去横向比较。路由只保留判别信息（谁唯一给什么、谁有什么缺口），不重述参数。
5. **有意识丢弃**：API endpoint 映射表不搬——CLI 使用者不需要 HTTP 端点；README 的开发/构建章节与 agent 无关。README 里的命令示例与请求体映射也不搬，`--help` 已是更精确的来源。

## 后果

- 执行路径不再包含「解析 `npm root -g` 再读 460 行 README」。
- 域文档中的字段表是 `0.1.14` 的快照，升级后若无人核对版本标注会静默过期——这是已接受的成本，由前置检查的版本比对兜底。
- 新增一处维护点：升级 dida-cli 后，需按版本标注校对两份域文档。
