# ADR-0017：判定 agent 与人工复核表只写报告，不参与判定

- 状态：接受
- 日期：2026-11-18

## 背景

ADR-0005 写着「质量维度（绕路、冗余操作、是否先读后改）交由判定 agent 写进报告，不影响通过或失败」，但没说清判定 agent 读什么、产出什么形状、失败时怎么办。同一时期 ADR-0014 取消了「评估」这个概念——不存在「算了但不计入判定」的结论。

两者看似冲突：判定 agent 的产出恰恰**就是**「算了但不计入判定」的结果。实现 #10 时必须先回答这个问题，否则报告里会出现第二组结论，正是 ADR-0014 要消除的形状。

同时，`#25` 的「客户端看不看得见」这半只能人工判断，需要一种在报告里声明「该去客户端看什么」的机制。

## 决定

### 判定 agent 的产出进报告，但不进判定链

ADR-0014 取消的「评估」指的是**判定链内部**的面：可信度检查、结局断言、过程断言各自算完后的中间结论。判定 agent 不在判定链上——它跑在判定链**之后**，读的是判定链已经定稿的事实（轨迹、调用日志、账本），产出的是给人读的评价。

因此：

- 它的结果写进 `manifest.judgement` 与 `report.md` 的「## 质量评价」小节；
- 它不出现在 `assertion` 里，不产生 `status`，不影响 `ok`、退出码、清场门控；
- 判定 agent 失败时折成 `judgement.status: 'missing'`，**报告照常渲染这一段**，写明缺失原因。

最后一条是关键：把缺失的段落整节省略，读者会以为这次评过、只是没发现问题——那是把没做的事说成做了。

### 判定 agent 的读入是文件路径，产出是三个固定标题

prompt 里给出轨迹路径、调用日志路径、用户原话与建出的任务清单，要求按「## 绕路」「## 冗余操作」「## 先读后改」三个标题作答。

解析按**逐字**匹配这三个标题：判定 agent 换个说法（多空格、改措辞）就判「缺维度」，整段折成 `missing`。理由是这段评价的价值在于稳定可比——措辞漂移的评分，读的人无从在两次运行之间对照。缺维度时不写「其余两节 + 一节空白」，而是整段判缺失：半份评价冒充完整评价，比没有更糟。

### 判定 agent 走单独的 agent 定义，工具面只有只读

`harness/agents.json` 新增 `dida-judge`，工具面 `Read`、`Glob`、`Grep`，没有执行命令的能力。它不需要写文件（结论走 stdout），也不需要 PowerShell。

它不以运行目录或仓库为 cwd：那会继承 `CLAUDE.md` 与那里的 skill，判定 agent 读的是会话记录，不是项目说明。

### 判定 agent 不属于探针

探针没有判定要评，它的产物是给人写断言用的样本（ADR-0015）。探针不启动判定 agent，报告里没有质量评价段。

### 人工复核表在 `scenario.json` 的 `review` 里声明

```json
{
  "prompt": "…",
  "review": [{ "title": "CHECKLIST 任务（任务 id）", "expect": "标题、5 条检查事项、说明文本" }]
}
```

报告把它渲染成「## 人工复核」小节。形状写错（缺 `title` 或 `expect`）时报告点出这一条缺什么，不让整次运行停下——它是给人看的清单，不是判定依据。

## 被否掉的替代方案

**把质量评价写成第四个断言面。** 直接违反 ADR-0014 与 ADR-0005：评分随措辞漂移，红绿信号会被模型的语气污染。

**判定失败时整段省略。** 读者分不清「没评」与「评了没问题」。

**人工复核表单独落一份文件。** 报告是这次运行的唯一读入口；第二份文件会与报告各自漂移，也容易被忘记。

**人工复核条目自动从账本生成。** 账本只知道 id 与标题，不知道「应该看到什么」——预期内容只能由用例作者声明。

## 后果

- 每条 scenario 多一次短会话的成本（判定 agent 只读几个文件）。
- 判定 agent 的输出稳定性依赖 prompt 里的三个固定标题；改标题就是改报告格式。
- 人工复核表要靠人真的去看，报告只是把「该看什么」摆出来。
