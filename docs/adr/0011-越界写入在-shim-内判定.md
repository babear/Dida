# ADR-0011：越界写入在 shim 内判定，逐命令声明目标而不是猜位置参数

- 状态：接受
- 日期：2026-11-10

## 背景

ADR-0004 定下了"越界写入根本发不出去"的目标与拒绝文案；`docs/specs/dida-cli-skill-评测平台.md` 的「shim 规则」段写了三条解析规则（`create` / `update` 取 `--project`、`move` 取 `--from` 与 `--to`、其余取位置参数）。实现时对照真 CLI 0.1.14 的 `dist/commands/*.js` 逐条核对，发现这三条规则直接照做会出错：

1. **位置参数不都是 projectId。** `project group update <groupId>`、`habit update <habitId>`、`focus update <focusId>` 的位置参数 1 不是清单 id。按"位置参数 1"泛化会误判，或者更糟——把该拦的漏掉。
2. **`task update` 的定位键不是位置参数。** `api.updateTask(taskId, {id: options.id, projectId: options.project})` 里 URL 用的是位置参数、body 里的 `id` 是 `--id`。两者不一致时，一次 `--project <测试清单>` 的调用仍可能在改别的清单里的任务。
3. **`task complete-batch` 的 `--project` 是可选的**，省略即写收集箱。spec 里"create/update 必填所以漏传不成问题"的论证只对这两条成立。

## 决定

- **逐命令声明表**（`harness/lib/guard.mjs` 的 `WRITE_COMMANDS` / `READ_COMMANDS`）。每条写命令显式写明目标从哪个 flag 或第几个位置参数取；没有目标的写命令记成空表项并拒绝。不靠"位置参数 1"兜底，表里没有的命令按未知拒绝，不默认放行。
- **一条规则**：对写命令解析目标清单；解析不出目标，或目标不在测试清单集合内，就拒绝。缺 `--project`、空值 `--project=`、没有清单参数的写命令走同一个出口，不设"未传则放行"的分支。
- **`task update` 要求位置参数 `<taskId>` 与 `--id` 相同**，否则拒绝（`id-mismatch`）。
- 参数解析复刻 commander 语义：`--` 之后一律当位置参数；带值选项的第一个值**无条件消费**（即使以 `-` 开头），variadic 从第二个值起才遇 flag 停止；重复 flag 全部校验。`--help` / `--version` 只有作为独立选项时才当帮助放行——实测 `task create --title --help --project <清单>` 与 `task move --to <清单> --task --help` 里它是**值**，真 CLI 会照常执行，见到这个字符串就放行等于把写命令放出去。
- `task update` 的 `--id` 重复时按 commander 的"后写覆盖"比较最后一个；重复值彼此不同也拒绝。
- 只给出命令组（`dida task`）或 `task help` 时不执行任何 action，照常放行。
5. 拒绝文本用 **404 + `resource_not_found`**（真 CLI 实测存在的形态），不用 ADR-0004 里未实证过的 403；`errorId` 每次随机。退出码用 1。

## 考虑过的方案

- **通用"位置参数 1"规则**：代码最少，但上面第 1 条会让 `project group update` 之类被误判或被漏判，且新增命令时容易静默出错。
- **`create` / `update` 缺 `--project` 时放行**，让真 CLI 自己报 required option：错误文本与真 CLI 完全一致，但判定表多一个分支，且"缺参"与"越界"两种拒绝在日志里形态不同。
- **用 403**：ADR-0004 的原文，但没有实测证据；遇到 404 的真 CLI 行为更可信。

## 后果

- `task create` / `task update` 缺 `--project` 时，错误文本从真 CLI 的 `error: required option '--project <projectId>' not specified` 变成伪造的 `DIDA API 错误 404`。两条路都写不出去，区别只在文本是否逐字相同。
- `habit *`、`focus *`、`tag *`、`project create`、`project group *` 一律拒绝：scenario 里无法新建清单、打卡或改标签。真需要放开时，改动点是 `WRITE_COMMANDS` 里那几条空表项。
- 真 CLI 新增命令时，必须同步 `guard.mjs`；漏掉的那条会以"未知命令"被拒，不会静默放行——失败方向是安全的一侧。
- 被拒的调用只进调用日志（`decision: rejected`），不进账本；过程断言读调用日志即可看到"曾经试图越界"。
